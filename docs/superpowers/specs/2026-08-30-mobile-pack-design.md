# Мобильный пакет: вертикальная flow-диаграмма, компактная шапка консоли, тап-таргеты

Дата: 2026-08-30. Статус: дизайн одобрен пользователем (аудит адаптивности:
десктоп/ноутбук в порядке; на смартфоне подписи flow-SVG 4.2px — нечитаемо).

## Принципы

Ни одного нового видимого текста: вертикальная диаграмма дословно реиспользует
строки горизонтальной. Тексты и разметка остальных секций не меняются.
Десктоп (>900px) и ноутбук (761–900px) не затрагиваются визуально ничем,
кроме самих media-правил ≤760px. Все новые анимации — внутри
`@media (prefers-reduced-motion: no-preference)`; при reduce частицы скрыты
(как у горизонтальной версии). Бэкенд/тесты/console.html/app.js не трогаются.

## 1. Вертикальная flow-диаграмма (index.html + front.css)

- В секцию `.flow-sec`, сразу после существующего `.flow-svg`, добавляется
  второй инлайн-SVG `.flow-svg-m` (`aria-hidden="true"`), вертикальная
  композиция viewBox ≈ 340×430: узел `EVERY TRADE` / `pays 3%` сверху по
  центру, три русла вниз к трём строкам:
  `80%` + `GenomVault — the holders' basket`,
  `13%` + `the agent's operations`,
  `7%` + `the protocol` (дословный реюз, другие строки запрещены).
- Частицы: те же размеры/плотность 4/2/1, новые классы `.fdm*` со своими
  `offset-path` под вертикальные русла, keyframes `flowmove` реиспользуется.
  Скорости/задержки — в духе горизонтальной версии.
- Переключение только CSS: по умолчанию `.flow-svg-m { display: none; }`;
  в `@media (max-width: 760px)` — `.flow-svg { display: none; }
  .flow-svg-m { display: block; }`. Плотность/анимации частиц `.fdm` — в
  `no-preference`; в `@media (prefers-reduced-motion: reduce)` скрывается
  группа точек мобильной версии (аналог `.flow-dots`).
- Типографика внутри мобильного SVG подбирается так, чтобы на ширине 375px
  эффективный размер подписей был ≥11px (pct — заметно крупнее).

## 2. Компактная шапка консоли ≤760px (app.css)

- Только сжатие: уменьшенные вертикальные поля/гэпы `.top`, контролов
  `.ctl`/`select` и `#topStats` в существующем media-блоке
  `@media (max-width: 760px)` app.css. Ничего не скрывать.
- Цель: высота `.top` на 375px ≈ 180px (сейчас 243px); допуск ±15px.

## 3. Тап-таргеты ≤760px (front.css + app.css)

- `.lnk`, `.hd-console` (front.css) и `.navlink` (app.css) в media ≤760px
  получают вертикальный padding, дающий эффективную высоту зоны нажатия
  ≥32px. Визуально макет не «разъезжается» (padding, не margin; underline
  остаётся на месте).

## Критерии приёмки

1. 375px: вертикальная диаграмма видна вместо горизонтальной, частицы бегут
   по трём руслам (4/2/1), подписи ≥11px эффективных; горизонтальная
   диаграмма скрыта. 761px+: всё ровно как сейчас (горизонтальная).
2. Ноль горизонтальных переполнений на 375/768/1280/1680 (обе страницы).
3. Шапка консоли на 375px ≈ 180px, все контролы видимы и работают.
4. Reduced-motion: частицы мобильной версии скрыты, статика корректна
   (проверка код-ревью: анимации в no-preference, reduce скрывает точки).
5. Тесты 46/46; `node --check front.js` (если front.js менялся — п.1 его не
   требует, JS-изменений нет); ноль ошибок консоли браузера; скриншоты
   пользователю (375 / 768 / 1280).

## Вне объёма

Тексты, десктопная/ноутбучная вёрстка, fluid-типографика, console.html,
app.js, бэкенд, новые брейкпоинты кроме использования существующих ≤760px.

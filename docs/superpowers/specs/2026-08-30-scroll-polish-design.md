# Плавность скролла: каскад, глубина, линия прогресса (пакет «Глубина»)

Дата: 2026-08-30. Статус: дизайн одобрен пользователем (пакет №2 из трёх;
замеры до работ: 60fps, 0 jank-кадров на 300-кадровом скролл-прогоне).

## Принципы

Только transform/opacity (без layout/paint-тяжёлых свойств). Всё новое
движение — внутри `@media (prefers-reduced-motion: no-preference)` и/или
за флагом `REDUCED` в front.js. Тексты и разметка смыслов не меняются;
консоль не трогается. После внедрения тот же 300-кадровый прогон обязан
показывать 0 кадров >20ms.

## 1. Каскад появления элементов списков (front.css, чистый CSS)

Сейчас все `.rv`-элементы, оказавшиеся в кадре одновременно, получают
`.in` в один кадр и всплывают синхронно. Добавить нарастающие задержки
через существующую переменную `--d` (её уже читает анимация `rv`):

- `.ledger li.rv` — nth-child лесенка ≈ 70ms на шаг (7 шагов);
- `.ph li` — ≈ 90ms на шаг (4 фазы);
- `.worst`-колонки — ≈ 110ms на колонку (3 шт; точный селектор колонок
  уточняется по разметке в плане);
- список `.dna-list li` — каскад ≈ 80ms относительно появления родителя
  `.dna-wrap.rv.in` (сами li сейчас не `.rv` — анимация вешается через
  родителя, только в no-preference).

При reduced-motion существующее правило (`.rv, .rv.in { opacity: 1;
animation: none; }`) уже гасит всё; для новых дочерних анимаций —
аналогичное гашение.

## 2. «Прорисовка» штрих-кодов (front.css, чистый CSS)

Тики `.seq-rule i` при появлении родительского `.sec-head.rv.in`
проявляются слева направо: opacity 0→(их текущая) с задержкой ≈ 25ms на
тик (16 тиков ≈ 0.4s волна). Только в no-preference; при reduce тики
статичны с текущими прозрачностями.

## 3. Многослойный параллакс глубины (front.js)

Один общий passive scroll → rAF обработчик (расширение паттерна
существующего hero-ghost параллакса, за `!REDUCED`):

- контурные номера секций `.sec-idx` (4 шт): дрейф ≈ −0.05 от смещения
  элемента относительно центра вьюпорта (движутся чуть медленнее текста),
  кап ±18px; поверх их существующего `transform: translateY(2px)` — базис
  сохраняется (итоговый transform = базис + дрейф);
- видимая flow-диаграмма (`.flow-svg` или `.flow-svg-m`) и спираль
  `.dna-helix svg`: дрейф ≈ +0.04, кап ±14px (движутся чуть быстрее —
  ощущение переднего слоя).

Обрабатываются только элементы в пределах ±1 вьюпорта от кадра; ≤7
элементов за кадр, только чтение rect + запись transform.

## 4. Линия прогресса скролла (index.html + front.css + front.js)

- `<div class="scroll-progress" aria-hidden="true">` фиксированной высоты
  2px, прижата к самому верху окна (над бордером шапки), z-index выше
  шапки; заливка — гель-градиент (`--ice` → УФ), свечение `--glow-gs`.
- Ширина через `transform: scaleX(0..1)` (origin слева) — обновление в том
  же rAF-обработчике из п.3: доля прокрутки страницы.
- При reduced-motion линия остаётся (движение только от руки
  пользователя), но без transition-сглаживания.

## Критерии приёмки

1. Визуально: шаги/фазы/колонки всплывают лесенкой, штрих-коды
   прорисовываются, номера секций и диаграммы едва заметно расслаиваются
   при скролле, вверху растёт тонкая линия прогресса.
2. Повторный 300-кадровый скролл-прогон (тот же скрипт замера): 0 кадров
   >20ms, 0 long tasks.
3. Reduced-motion (код-ревью + эмуляция при возможности): каскады и
   параллакс выключены, тики статичны, линия без сглаживания.
4. Мобильный 375px: всё работает, переполнений нет; ноль ошибок консоли
   браузера; тесты (58) зелёные; `node --check front.js`.
5. Прод: после мержа — деплой и та же проверка на
   https://genom-iota.vercel.app.

# Рерайт всех текстов сайта nostro.capital

Дата: 2026-08-29. Статус: дизайн одобрен пользователем в чате.

## Цель

Перефразировать весь видимый посетителю текст сайта **без малейшей потери
смысла**: каждая фраза переписана заново (другие слова и синтаксис), но
каждое утверждение оригинала сохранено и ни одного нового не добавлено.
Язык остаётся английским. Стилистика сайта (верхний регистр заголовков,
«терминальный» тон, лаконичность) сохраняется.

Решения пользователя: объём — все три слоя текста (HTML-статика, строки из
JS, тексты с бэкенда); язык — английский; степень — глубокий рерайт.

## Объём — шесть файлов

1. **index.html** — герой (кикер, заголовок, подзаголовок, кнопки), секция
   MECHANICS (шаги 00–06: заголовки и абзацы), PROOF (терминал-карточка и
   боковой текст), WORST CASE (A/B/C), ROLLOUT (P0–P3), финальный блок,
   футер, `<meta name="description">`.
2. **console.html** — заголовки карточек и их «cn»-ярлыки допускается
   перефразировать только там, где это описательный текст, а не имя
   сущности; подсказки (`act-hint`, `foot`), тексты кнопок-действий,
   алерты, футер. Плейсхолдеры `aria-label` — тоже текст.
3. **front.js** — строки состояния (`CONNECTING`, `NODE OFFLINE — RUN:
   python3 server.py`, `SIM DATA / LOCAL NODE / CONCEPT V0.1`,
   `STANDBY / LAUNCHING ON PONS V2`, `LIVE ON-CHAIN`, standby-подписи),
   статусы commit-терминала («thesis sealed until…», «revealed /
   keccak256 verified…»).
4. **app.js** — все отображаемые строки: заголовки live-ячеек, бейджи
   track record («thesis sealed», «keccak verified», «mismatch — failed»),
   алерты брейкера и hold-режима, футноты таблиц и карточек, статусы
   действий кошелька, названия фаз в governance (только display-массив
   `names`), подписи легенды.
5. **server.py** — тексты, которые видны на сайте: шаблоны тезисов агента
   (`THESIS_LEADS`/`THESIS_TAILS`), все сообщения `self.log(...)`,
   `detail`-строки восьми guard-проверок, **названия** guard-проверок
   (`name`), лейблы голосований (`label`). Названия проверок — видимый
   текст; их можно менять, синхронно правя тест.
6. **tests/test_server.py** — единственная зависимость от текстов:
   `test_guard_checks_present_and_named` сверяет точный список названий
   проверок; обновляется вместе с server.py в одном коммите.

## Правила неизменности (нарушать нельзя)

Дословно сохраняются:
- имена сущностей и продуктов: $NSTRO, NSTRO, Nostro, Nostro Agent,
  Pons V2, Robinhood Chain, Uniswap V4 (v4), USDG, MandateGuard,
  CommitStore, NostroVault, NostroBasket, NostroCommits, AgentTreasury,
  keccak256, abi.encode, Merkle, MetaMask/Rabby, Blockscout;
- тикеры (AAPL … PLTR), имена/адреса холдеров, все адреса 0x…, URL;
- все числа, проценты, соотношения (3%, 80/13/7, 1%, ≤35%, ≥5%, ≤20%,
  −25%, 7 epochs, 3-day/3-epoch timelock, 4663, chain id, 12 seconds,
  800k, 0–100%);
- код, формулы и команды: `keccak256(abi.encode(epoch, weights,
  thesisText, nonce))`, `python3 server.py`, `./nstro connect <vault>
  [rpc]`, `./nstro sim`, `processWETH()`, сигнатуры функций;
- вся логика: id, классы, data-атрибуты, ключи JSON-контракта, сравнения
  строк в коде (`h.kind === "user"`, `action === "phase3"` и т.п.),
  format-спецификаторы (`%s`, `%d`, `%.2f`, `%%`-экранирование при
  %-форматировании) и структура конкатенаций в JS.

HTML-разметка не меняется (теги, атрибуты, порядок секций) — только
текстовые узлы. Число элементов ленты-тикера и прочая структура — как есть.

## Критерий приёмки «без потери смысла»

Для каждого абзаца/строки оригинала: (а) все факты и утверждения
присутствуют в новой формулировке; (б) новых утверждений нет; (в) фраза
не совпадает с оригиналом дословно (кроме защищённых токенов выше).
Проверяется предложение-за-предложением на ревью диффа.

## Верификация

1. `python3 -m unittest tests.test_server -v` — 46/46 (после синхронного
   обновления теста названий проверок).
2. `node --check front.js && node --check app.js` — синтаксис цел;
   `python3 -m py_compile server.py`.
3. `git diff --word-diff` — изменения только внутри строковых литералов и
   текстовых узлов; ни одного изменённого id/класса/атрибута/ключа.
4. Браузер: лендинг и консоль живые, ноль ошибок в консоли браузера, все
   карточки заполняются, статусы/бейджи/алерты показывают новые тексты
   (брейкер и hold проверяются форс-сценарием через API либо чтением
   строк в diff — визуально достаточно основных состояний).

## Вне объёма

README.md и docs/ (не «сайт»), русский перевод, изменение дизайна/CSS,
структуры страниц или поведения. Комментарии в коде не трогаем (они не
видны посетителю); при этом их соответствие новым строкам не требуется.
